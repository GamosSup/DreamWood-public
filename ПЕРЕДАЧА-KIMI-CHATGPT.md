# Передача изменений для Kimi и ChatGPT · 04.11.2026

Изменения внёс Claude по задаче руководителя парка. Перед своей работой прочитайте этот файл и `AGENTS.md`.

## Что изменилось

### v183 · опубликовано 04.11.2026 19:18
- `companion.js`: в окне выбора настроения и в журнале настроения заменён текст о том, кто видит запись. Новый текст: «Коллеги твою запись не видят. Если выберешь «Тяжело», руководитель получит сигнал, чтобы поддержать тебя.»
- Версия поднята в `index.html` и `sw.js` до 183.

### v184 · отправлено в main, публикация в очереди GitHub
- `app.js`:
  - `refreshUnread()`: для администраторов считает непрочитанные сигналы из `mood_alerts` и записывает их в `S.moodN`.
  - `paintBell()`: к числу на колокольчике добавляется `S.moodN`.
  - `openBell()`: вверху списка уведомлений показываются сигналы «Тяжело» за 7 дней. При открытии колокольчика они отмечаются прочитанными (`read_at`).
- Версия поднята в `index.html` и `sw.js` до 184.

### База Supabase (кода в репозитории нет)
- Новая таблица `public.mood_alerts`: `id, to_user, from_user, who, day, created_at, read_at, seen_by_claude`. RLS включён:
  - строку читает только адресат (`to_user = auth.uid()`);
  - адресат может отметить строку прочитанной.
- Новая функция `public.trg_mood_alert()` и триггер `mood_alert` на `mood_entries` (after insert or update of mood).
  - Срабатывают, когда сотрудник выбирает «Тяжело» (mood = 1) за сегодняшний день.
  - Создают по сигналу для двух администраторов.
  - Push в браузер не отправляют.
- Сигнал **намеренно не пишется в `notifications`**. Правило `notif manager write` даёт всем менеджерам доступ ко всем строкам `notifications`, а сигнал о настроении должны видеть только два администратора.
- Раз в час Claude читает новые сигналы и присылает уведомление руководителю. После этого он ставит `seen_by_claude = true`.
